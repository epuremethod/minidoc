summary: Build, watch, rebuild on change and serve the output with live reload.

signature: |-
  function dev(options: DevOptions): Promise<Server>

  type DevOptions = WatchOptions & {
    serve?: string
    port?: number
    edit?: string[]
  }
---

#### Options

Every option of [`watch`](#watch), plus:

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `serve` | `string` | `"dist"` | The folder served, relative to `root`. |
| `port` | `number` | remembered | A fixed port. Skips the remembered port and writes nothing. |
| `edit` | `string[]` | `[]` | Folders, relative to `root`, whose markdown files a page may read and write. |

#### Behavior

- Builds once, then rebuilds as [`watch`](#watch) does.
- Serves `serve` as static files. `/guide/` answers with its `index.html`;
  `/guide` with `guide.html`, then `guide/index.html`.
- Each served HTML page gets one injected line: an `EventSource` that reloads
  the page when a build lands.
- A failed build reloads nothing. The page stays as it was and shows the
  failure at its foot, with what the build script printed, until a build
  lands. A page opened while the build is broken shows the same.
- The failure has a close button. Closing it hides this failure; the next
  failed build shows its own.
- A content error is one line, in the terminal and on the page, even from a
  build script that does not catch it. A bug, such as a `TypeError`, keeps
  its stack.
- The build script must write over the old output, never empty the folder
  first: `dev` serves that folder while the script runs, and after a failed
  build it is all there is.
- Requests outside the served folder answer `403`.

#### Editing

- With `edit`, a page reads a markdown file of those folders with
  `GET /__minidoc/file?path=…`, and writes it with `PUT` and a JSON body
  `{text, base, page}`: the new text, the text it was written over, and the
  page's name.
- A write over a file that is no longer `base` answers `409`, with the
  file as it is, and writes nothing.
- A path outside those folders, a new file, a file that is not markdown, a
  request without the `x-minidoc-edit` header, and a request from another
  origin answer `403`. Without `edit`, there is no such route.
- The reload stream names its page. A build made only by one page's own
  writes reloads every other page; that page is told the build landed, and
  keeps its caret. Any other change reloads every page.

#### The port

- Without `port`, the port is read from `var: port:` of the entry config.
- On first launch there is none: a free port is drawn and written there. The
  config is rewritten through yaml's document API; comments and layout stay.
- The remembered port is never replaced. When a minidoc dev server already
  answers on it, `dev` prints its address and returns. When anything else
  holds it, `dev` fails.

#### Returns

A [`Server`](#watcher): `port`, and `stop()` to stop watching and serving.

#### Example

```js
import { dev } from "@minidoc/core"

await dev({
  glob: "content/**/config.yaml",
  build: "src/build.mjs",
  watch: ["../shared"],
})
```
